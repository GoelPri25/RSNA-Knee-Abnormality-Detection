# Fit160 field-of-view comparison

## Question

Does the 140 mm center crop used by the 0.918 HPO-v1 ResNet-34 remove useful
peripheral anatomy? This run changes only the preprocessed image cache. It uses
the same HPO-v1 labels, added 281 training-only studies, fixed fold-0 validation
IDs, ResNet-34 reader, 24 sampled slice windows, optimizer, scheduler, and early
stopping rules as the 0.918 submission.

## Input data

The Fit160 cache is already generated by Priya's four completed Kaggle
notebooks. It contains three disjoint weak-label shards (1,456, 1,466, and
1,427 studies; 4,349 total) and a separate 58-study gold cache. All summaries
report 224-pixel images, four series slots, 12 slices per slot, the same
central-slice band and clipping percentiles, and zero decode errors, skipped
slots, or missing spacing. Each manifest points to both intensity and support
arrays.

The weak data and separate gold images are copied directly from Kaggle kernel
outputs onto a dedicated Modal volume, `rsna-cnn-fit160-cache-v1`. Staging is a
CPU-only task and commits each complete file so it can resume after interruption.
The gold images are stored for traceability but are not used by the training
run; gold labels remain locked.

## Single preprocessing change

The original cache extracts a centered 140 mm physical crop and resizes it to
224 × 224. Fit160 fits the scan into a canvas of at least 160 mm (`fov_mode=fit`)
and resizes that to 224 × 224. The larger view may retain more peripheral
context, while reducing pixels per millimeter. The actual view can exceed
160 mm when the scan's physical extent is larger.

## Training and safeguards

- One personal Modal T4; fold 0 only.
- HPO-v1 labels for training; the 281 studies without the original fixed fold
  assignment join training only.
- The same 825 fold-0 report-validation studies are scored against Steven v4.
- 60-epoch ceiling, ReduceLROnPlateau on validation BCE (factor 0.5, patience 2),
  best-checkpoint selection and early stopping on report-validation macro AUC
  (patience 8, minimum improvement 0.0005).
- Checkpoints and metrics are published to a private Kaggle dataset every two
  epochs, with the final state published at completion.
- The run stages all cache files before it requests the T4. It is launched
  detached using `scripts/run_modal_personal_fit160.py`, which strips work
  Modal credentials and reads only `~/.config/rsna/modal-personal.env`.

The expected weak-cache footprint is about 19.5 GiB for intensity and support
arrays together, plus roughly 0.3 GiB for the gold image cache and small
manifests. Kaggle remains the durable source of truth for the caches and
training artifacts; this Modal volume is a working copy for compute reuse.

## How to interpret the result

The primary comparison is the public score against 0.918. Report-fold AUC and
BCE are diagnostics, not substitutes for the competition score. If Fit160
improves, it supports the hypothesis that peripheral context matters. If it
does not, the 140 mm view likely provides a better context/detail tradeoff for
this reader. Because this is a single fold and one submission, treat a small
score change as inconclusive.
