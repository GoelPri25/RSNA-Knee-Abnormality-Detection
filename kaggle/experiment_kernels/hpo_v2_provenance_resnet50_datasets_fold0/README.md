# HPO v2 provenance ResNet-50 fold 0 (dataset-mounted cache)

This is a Kaggle **script kernel** for a label-only comparison against the HPO v1 +281 ResNet-50 run. Its training recipe is based on the **successful Kaggle two-T4 ResNet50 runner** at `kaggle/experiment_kernels/hpo_v1_blend_resnet50_t4x2/run.py`, not an assumed Modal-only recipe. The backbone, ImageNet initialization, 24 windows, global batch of 8, DataParallel placement, trainer, optimizer, schedule, fixed fold-0 validation, and checkpoint rules stay the same. The intended training change is the HPO v2 provenance candidate labels.

The three original 140 mm cache shards are attached through the same Kaggle kernel-output inputs used by the successful ResNet50 run. The rehosted copies attached as `dataset_sources` repeatedly failed at Kaggle startup before Python ran. A CPU-only preflight passed for all three original shard inputs and verified the required cache files. The HPO-v2 label dataset also passed a separate CPU-only mount check; source code and Steven-v4 validation labels remain attached as datasets.

The runner uses explicit input paths and saves checkpoints/history in `/kaggle/working` each epoch. It reconstructs the 281 train-only fold assignments from the verified 4,068-row base split and the HPO-v2 label IDs, matching the successful Kaggle runner. It no longer expects `report_folds_hpo_add281_trainonly.csv` inside the source dataset, where that file is absent.

The initial v2 wrapper had two defects compared with the known-good Kaggle runner: it resolved cache directories with a file-only check (fixed in version 2), and it required the absent expanded-fold CSV (fixed in the current local runner). Neither defect changes the model recipe; both concern input setup. The earlier failed submission was packaged as a notebook; this revision uses the script-kernel format shared by both the successful Kaggle ResNet50 run and the teammate's successful run. The two new inputs have each mounted successfully in CPU-only preflights.
