## Why `experiment_kernels` must not be reused

It was generated by `scripts/prepare_kaggle_experiment.py` and never completed a run. Its
preprocessing differs from the verified pipeline in ways that change the embeddings:

- resamples with `F.interpolate` on the native `(slice, row, column)` axes instead of
  reorienting onto canonical DICOM LPS axes, so axial/coronal/sagittal acquisitions of the
  same knee land on different grids;
- takes intensity quantiles over the whole tensor rather than the reconstructed volume;
- hard-codes the image directory layout (`train_images/...`), which does not match the
  competition mount and is what caused version 1 to fail.

`scripts/prepare_kaggle_experiment.py` still emits that older pipeline and has not been
updated to the verified one.

## The verified pipeline

`milestone/pillar0_milestone.ipynb` is the notebook that was run cell by cell
against the mounted competition data. Committed as pulled, with outputs stripped by
Kaggle — it contains no competition imagery or identifiers.

    DICOM series
      -> geometry-validated reconstruction (physical slice order via ImagePositionPatient)
      -> canonical DICOM LPS resample, 1 mm isotropic
      -> high-contrast MR window (20th-99th percentile)
      -> centre pad/crop to 192 x 384 x 384
      -> single series repeated into 3 channels
      -> frozen Pillar-0 (revision be5050ba482607f90e607e044f03a2ebc38f98c3)
      -> 1152-D series embedding, unit norm
      -> masked attention aggregator (283,276 trainable parameters)
      -> 128-D z_study -> 12 logits

Running it requires a GPU, the competition dataset attached, and a Kaggle secret named
`HF_TOKEN` from a Hugging Face account that has accepted the gated Pillar-0 terms.

## Offline checkpoint deployment

`offline/pillar0-offline-load-test.ipynb` loads an immutable private Kaggle
notebook output containing the exact Pillar-0 revision, custom Python modules, ECL-2.0
license, source provenance and file checksums. Kaggle metadata records internet disabled.
Because Transformers' dynamic-module loader omitted a relative import offline, the
notebook copies only the custom Python modules into a temporary package. It constructs
the model on CPU and uses `torch.nn.Module.load_state_dict` to preserve the checkpoint's
`model.*` wrapper keys before moving the frozen model to the GPU.

## Report supervision audit

`../submission_kernels/report-label-audit.ipynb` audits report duplication and writing systems,
creates a reproducible 29/29 development/evaluation split of the 58 gold studies, and
evaluates a frozen conservative Qwen3-4B extractor. It retains four evidence states plus
severity and negation. `uncertain` and `not_mentioned` remain masked. Locked evaluation
gave 0.7029 micro positive precision, 0.9130 micro negative precision, 0.6609 resolved
coverage and 0.8124 macro neutral-unknown AUROC.

The same notebook benchmarks the proposed production configuration: two T4 replicas,
eight reports per GPU, deterministic generation and a projected 6.55-hour runtime for
all 4,407 reports. The source has no outputs, report text or credentials. The full run
belongs in a separate resumable notebook.
